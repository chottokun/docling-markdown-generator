# Markdown出力仕様 (Markdown Specification)

本ライブラリは、Doclingを用いて高度に構造化されたMarkdownを生成します。特に図（画像）の埋め込み、キャプションの保持、および複雑な表の変換において、LLMが理解しやすい形式を維持します。

## 0. メタデータ (YAML Frontmatter)

生成されるMarkdownの先頭には、ドキュメントのメタデータがYAML形式で付与されます。
```yaml
---
title: ドキュメントのタイトル
# 今後の拡張予定
# document_type: 契約書
# page_count: 10
---
```
これにより、LLMは文書全体の文脈（どの文書を読んでいるか）を即座に把握できます。

## 1. 図（画像）の表現

### 埋め込み形式
図は標準で CommonMark / GFM 規格に準拠した以下の形式で参照されます（VS Code, GitHub, 各種プレビューアーで100%インライン表示可能）。
```markdown
![picture_1.png](assets/doc-slug/picture_1.png)
```
- **保存場所**: 指定された `assets_dir` （または出力ディレクトリ配下）に保存されます。
- **リンクのカスタマイズ**: `EnhancedDoclingConverter` 利用時、`image_tag_template` オプションを指定することで Obsidian 形式 (`![[assets/{slug}/{image_name}]]`) などの独自タグへ変更可能です。

### キャプションの抽出
Doclingの解析により、図に関連付けられたテキスト（図表番号や説明文）を可能な限りキャプションとして抽出します。

## 2. 表（テーブル）の表現

複雑なドキュメント（セルの結合があるPDFやExcelなど）に対応するため、表は **HTML (`<table>`) 形式** で Markdown 内に埋め込まれます。
- **高精度な構造保持**: `rowspan` や `colspan` を用いて、セルの結合を正確に維持します。
- **LLMフレンドリー**: 最近のLLMは Markdown 形式よりも HTML 形式のテーブルの方が、複雑なデータ構造を正確に理解できる特性があります。
- **アクセシビリティ**: 構造が維持されるため、LLMによるデータ抽出や分析（RAG等）において、列と行の関係を間違えることなく処理できます。

## 3. 文書構造

- **階層構造**: 見出し（# ## ###）が文書の論理構造に基づいて生成されます。
- **数式 (LaTeX)**: 科学技術文書に含まれる数式は、高精度な **LaTeX 形式** で抽出・変換されます。これにより、LLMは数式の論理的意味を正確に解釈可能です。
  さらに、本ライブラリは、出力するMarkdownビューアやLLM、RAGパーサーへの最適化のために**数式フォーマットのカスタマイズおよび自動判別機能**を提供しています。

  ### ⚙️ 数式フォーマット調整オプション
  以下のオプションを、API（Form）、CLI（コマンドライン引数）、または `DocumentConversionOptions` から指定可能です。

  | オプション名 | 既定値 | 説明 | 指定可能な値 |
  | :--- | :--- | :--- | :--- |
  | `math_inline_delim` | `"auto"` | インライン数式の囲み記号（デリミタ） | `"auto"`, `"$"` など任意の文字列 |
  | `math_block_delim` | `"auto"` | ブロック数式の囲み記号（デリミタ） | `"auto"`, `"$$"`, `"\["` など任意の文字列 |
  | `math_block_newline` | `"auto"` | ブロック数式のデリミタの内側での改行有無 | `"auto"`, `true` / `"true"`, `false` / `"false"` |

  ### 🧠 自動判別 (`"auto"`) の詳細ロジック
  既定値（`"auto"`）では、以下のインテリジェントなヒューリスティクスが自動的に適用されます。

  1. **デリミタの自動選択 (ドキュメント形式による判別):**
     - **LaTeXソースドキュメント (`.tex` または `.latex` 形式):**
       LaTeXとの整合性を重視し、標準的な**括弧表記**（インラインは `\(` / `\)`、ブロックは `\[` / `\]`）を自動的に選択します。
     - **その他のドキュメント (PDF, HTML, Office 形式など):**
       一般的なMarkdownレンダラー（Obsidian, Notion, GitHub等）やLLMで最も幅広くサポートされている**ドル表記**（インラインは `$` / `$`、ブロックは `$$` / `$$`）を自動的に選択します。
     - *※開括弧デリミタ（例: `\(` や `\[`）が指定または自動選択された場合、閉じデリミタは対応する適切な閉括弧（`\)` や `\]`）へと自動的にマッピング・出力されます。*

  2. **ブロック改行の自動選択 (数式の複雑さによる判別):**
     ブロック数式の内部に改行を挿入して複数行表示にするか、1行に集約するかを、数式の構造的複雑さに応じて動的に切り替えます。
     - **改行あり（複数行レイアウト）となる条件:**
       - 数式内に改行コード `\\` が含まれる場合（行列や数式アライメントなど）
       - 数式内に LaTeX 環境命令 `\begin` または `\end` が含まれる場合
       - 数式自体の長さ（文字数）が **60文字** を超える場合
     - **改行なし（1行レイアウト）となる条件:**
       上記に該当しない、シンプルで短い数式（例: `E = mc^2` など）の場合。
       これにより、無駄な空行や空トークンの消費を徹底的に抑え、スリムなマークダウン出力を実現します。
- **リスト**: 箇条書きや番号付きリストが正確に再現されます。

## 4. RAG最適化機能 (RAG Optimization)

RAGでの利用を想定した以下の拡張機能が利用可能です。

### Key Information (Markdown KV)
`include_kv_extraction` を有効にすると、ドキュメントから抽出された主要な属性が Markdown のリスト形式で挿入されます。
```markdown
## Key Information
- **Extraction Status**: Placeholder
```

### ページ境界マーカー (Page Markers)
`include_page_breaks` を有効にすることで、セグメンテーション（チャンキング）を容易にするマーカーが挿入されます（将来の拡張）。

## 5. サポートフォーマット
以下のファイルから同様の品質のMarkdownを生成可能です。
- **PDF**: 高精度なレイアウト解析。
- **Office (DOCX, PPTX)**: スタイルに基づいた構造化。
- **Excel (XLSX)**: シートごとのテーブル変換。
